# 订单缓存优化说明

## 问题描述

原始代码中存在频繁调用券商API的问题：
- `[BaseTrader] Found 17 unfilled orders` 日志多次打印
- `_has_real_buy_order_at_price()` 和 `_sync_order_status()` 在同一个tick中重复调用 `get_unfilled_orders()`
- 每次调用都会执行 `self.xt_trader.query_stock_orders(self.stock_account)`，造成不必要的API开销

## 优化方案

### 1. BaseTrader层优化

**文件**: `md/xtquant交易/base_trader_zld.py`

#### 新增方法：
- `query_stock_orders_raw()`: 直接调用券商API获取原始订单数据
- `get_unfilled_orders(verbose=True)`: 添加verbose参数控制日志输出

#### 优化效果：
- 分离原始数据获取和数据处理逻辑
- 支持静默模式，避免频繁日志输出

### 2. GridStrategy层优化

**文件**: `src/网格/网格信号实盘/grid_strategy.py`

#### 新增缓存机制：
```python
# 在__init__中添加缓存变量
self._cached_orders: Optional[List[Dict]] = None
self._cache_timestamp: Optional[float] = None
```

#### 新增方法：
- `_cache_broker_orders()`: 在tick开始时缓存券商订单数据
- `_get_cached_orders()`: 获取缓存的订单数据
- `_sync_order_status_cached()`: 使用缓存数据同步订单状态

#### 修改方法：
- `_handle_level_event()`: 在tick开始时调用一次 `_cache_broker_orders()`
- `_has_real_buy_order_at_price()`: 使用 `_get_cached_orders()` 替代直接API调用

## 优化效果对比

### 优化前
```
每个tick的API调用次数：
- _sync_order_status() -> get_unfilled_orders() -> query_stock_orders()  [1次]
- _has_real_buy_order_at_price() -> get_unfilled_orders() -> query_stock_orders()  [多次调用]
总计：1 + N 次API调用（N为检查的网格层级数）
```

### 优化后
```
每个tick的API调用次数：
- _cache_broker_orders() -> query_stock_orders_raw()  [1次]
- _sync_order_status_cached() -> _get_cached_orders()  [0次API调用]
- _has_real_buy_order_at_price() -> _get_cached_orders()  [0次API调用]
总计：1次API调用
```

## 性能提升

1. **API调用频率降低**: 从每个tick 1+N次降低到1次
2. **日志输出减少**: 通过verbose参数控制，避免频繁打印 `[BaseTrader] Found X unfilled orders`
3. **响应速度提升**: 减少网络延迟，提高策略执行效率
4. **系统稳定性**: 降低对券商API的压力，减少被限流的风险

## 使用说明

### 正常运行
- 策略会自动在每个tick开始时缓存订单数据
- 所有订单相关操作都使用缓存数据
- 日志输出更加简洁

### 调试模式
- 如需查看详细的订单信息，可以临时启用verbose模式
- 可以通过日志 `[GridStrategy] Cached X unfilled orders for this tick` 确认缓存工作正常

## 兼容性

- 保持原有API接口不变
- 向后兼容，不影响现有功能
- 可以随时回滚到原始实现
